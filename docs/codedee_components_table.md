# CodeDEE: Complete Architectural Components Specification

ตารางสรุปพิมพ์เขียวสถาปัตยกรรมทั้ง 9 ชิ้นส่วนของ **CodeDEE** จำแนกบทบาทการทำงานระหว่าง **Symbolic** และ **Neural** โครงสร้างข้อมูล (Data Structures) เทคนิคที่ใช้ (Techniques) และทางเลือกอื่นในโลก (Alternatives) อย่างสมบูรณ์:

| # | ชื่อ Component | มิติการทำงาน (Symbolic vs Neural) | สิ่งที่ CodeDEE เลือกใช้ (Our Choice & Tools) | Data Structures & Techniques ที่ใช้ | ทางเลือกอื่นในโลก (Alternatives) | จุดเด่นที่ CodeDEE ชนะ |
| :-: | :--- | :---: | :--- | :--- | :--- | :--- |
| **C1** | **Frontend Parser** | **Pure Symbolic** | **Tree-sitter** (C-based GLR incremental parser รองรับ Python, JS, TS) | • **Data Structure:** Concrete Syntax Tree (CST)<br>• **Technique:** Incremental Parsing, Error Recovery | Standard AST (Python `ast`, Babel), ANTLR, Clang | เร็วระดับมิลลิวินาที, ไม่ตัด Comment/Whitespace (สำคัญต่อ Auto-fix), ซ่อมแซม Syntax Error ขณะพิมพ์ได้ |
| **C2** | **Graph Builder** | **Pure Symbolic** | **Unified Multi-Graph Engine** (`networkx` / In-Memory Graph) | • **Data Structures:** Call Graph (ข้ามไฟล์) + CFG + DFG/ODG (อิง USENIX 2022)<br>• **Technique:** Def-Use Chains, Scope Resolution, Object Dependence Tracking | Pure AST (ไม่มีกราฟเลย), Relational DB (CodeQL), Graph DB (Neo4j/Joern) | กินแรมน้อยกว่า Database หลายเท่า รันสดใน IDE ได้ทันที รองรับ Dynamic Object Properties ของ JS/TS |
| **C3** | **Traversal Engine** | **Neuro-Symbolic (Hybrid)** | **Two-Stage Engine:**<br>1. *Symbolic:* Worklist Taint Walker + Fast Pattern Matcher<br>2. *Neural:* Local LLM Semantic Oracle | • **Techniques:**<br>  1. *Dataflow Taint Analysis* (หา Injection ข้ามไฟล์)<br>  2. *AST Pattern Matching* (ตรวจ Secrets, Weak Crypto, Bad Config ใน 0.001s)<br>  3. *Neural Sanitizer Triage* (LLM ตรวจ Custom Sanitizer) | Pure AST Visitor (Bandit, ESLint), Datalog (CodeQL), Black-box DAST (ZAP), Pure LLM Scanner | ตรวจได้ทั้ง Injection และ Bad Config ทั่วไป ตัด False Positive ได้เฉียบคมด้วย LLM โดยไม่หน่วงเครื่อง |
| **C4** | **Rule Catalog** | **Pure Symbolic** | **Declarative YAML Rules** (อิง OWASP Top 10 Web, OWASP LLM 2025, CWE Top 25) | • **Data Structure:** Declarative Rule Schema (Sources, Sinks, Sanitizers, AST patterns)<br>• **Technique:** Boundary Specification Matching | Hardcoded Classes (Bandit), Datalog QL Libraries (CodeQL) | เพิ่ม/แก้ไขกฎง่าย ไม่ต้องคอมไพล์โค้ดใหม่ ครอบคลุมทั้ง Web ดั้งเดิมและช่องโหว่ AI ยุคใหม่ |
| **C5** | **Maintainability Engine** | **Pure Symbolic (คณิตศาสตร์ 100%)** | **SQALE Method (ISO/IEC 25010) + SIG Benchmark (Alves 2010)** | • **Data Structures:** CFG Decision Points, Call Graph Degree ($C_a, C_e$), Class LCOM4 Graph<br>• **Techniques:** Cyclomatic/Cognitive Complexity, LCOM4 Cohesion, Coupling Instability, SQALE TDR ตัดเกรด A–E | Hardcoded Numbers (`CC > 10`), Raw Maintainability Index (MI), Git Churn (CodeScene) | มีสูตร ISO/IEC สากลรองรับ ใช้สถิติ Percentile ถ่วงน้ำหนัก ไม่เดาตัวเลขมั่ว ไม่ต้องพึ่งพา AI |
| **C6** | **Program Slicer** | **Pure Symbolic** | **Backward & Forward Program Slicer** | • **Data Structure:** Program Dependence Subgraph (Slice 15–30 LOC)<br>• **Technique:** Program Slicing along def-use chains around ambiguous sanitizers | Whole-File Dump, Vector RAG (ChromaDB), AST Subtree Truncation | ลดปริมาณ Token ที่ส่งให้ LLM ได้กว่า 90%, ป้องกัน Token Window เต็ม และตัดอาการหลอน (Zero Hallucination) |
| **C7** | **Patch Synthesizer** | **Pure Neural** | **Local Code LLM** (`Qwen2.5-Coder` / `DeepSeek-Coder` ผ่าน Ollama)<br>*(รองรับ BYOK API Key & `vscode.lm` Copilot)* | • **Technique:** Automated Program Repair (APR), Context-aware Prompting<br>• **Output:** สร้าง Candidate Fix **อย่างน้อย 3 เวอร์ชัน** (Minimal, Refactor, Idiomatic) | Regex Replace (`eslint --fix`), Cloud API Only (GPT-4o), Genetic Repair (GenProg) | โค้ดความลับไม่รั่วไหลออกจากเครื่อง แก้ไขได้ทั้งช่องโหว่ความปลอดภัยและการ Refactor ลดความซับซ้อน |
| **C8** | **Verification Oracle** | **Pure Symbolic (ผู้คุมกฎทางคณิตศาสตร์)** | **Closed-Loop Multi-Gate Verifier** (ตรวจ 4 ด่านในหน่วยความจำ) | • **Techniques:**<br>  - Gate 1: Tree-sitter Re-parse (Zero Syntax Error)<br>  - Gate 2: Interface Preservation (Signature เดิม)<br>  - Gate 3: Taint Path Broken (ช่องโหว่หายจริง)<br>  - Gate 4: Maintainability Delta ($\Delta CC \le 0, \Delta \text{TDR} < 0$) | Blind Acceptance (ปล่อยผู้ใช้เสี่ยงเอง), Unit Test Only, SMT Solvers (Z3) | การันตี 100% ว่าโค้ดที่แก้ไม่พัง ไม่ทำลายระบบอื่น และคุณภาพดีขึ้นจริงทางคณิตศาสตร์ก่อนบันทึก |
| **C9** | **Developer Interface** | **Hybrid Presentation Layer** | **VS Code Extension (TypeScript/LSP) + CLI Tool** | • **Data Structure:** Diagnostic Problems List, Inline Code Actions<br>• **Technique:** Language Server Protocol (LSP), 1-Click Interactive Patch Application | CI/CD Gate Only (GitHub Actions), Standalone Web Dashboard (SonarQube) | ให้นักพัฒนาเห็นไฮไลต์สีแดงแบบ Real-time ขณะพิมพ์ใน IDE และมีปุ่มเปรียบเทียบ 3 เวอร์ชันกด 1-Click Apply ทันที |
