## 2. Logic Chain

1. **Def-Use Chain Disconnection**:
   In static analysis, taint flows along directed DFG edges (Definition -> Use -> Operation -> Definition ... -> Sink). If a variable reference is dropped during AST traversal, its Def-Use edge is never instantiated.
2. **Container Node Neglect**:
   Python and JavaScript both support collections and grouping constructs (`tuple`, `list`, `array`, `set`, `dictionary`, `parenthesized_expression`). Because Tree-sitter produces a dedicated wrapper AST node for each of these syntax forms, failing to handle container node types causes all expressions wrapped inside parentheses, brackets, or braces to be treated as opaque literal values.
3. **Formatting Operator Interaction**:
   In Python `%` formatting (`str % values`), `values` is almost universally a `tuple` (e.g. `query % (arg1, arg2)` or `query % (arg1,)`). Dropping `tuple` nodes directly blinds the taint engine to the primary syntax for string formatting in legacy and standard Python database code.
4. **Resolution Strategy**:
   `_process_expression` must implement recursive traversal for all collection and wrapper node types:
   - **Grouping syntax** (`parenthesized_expression`): Transparently unwrap and return the evaluated inner expression nodes.
   - **Collections & Sequences** (`tuple`, `list`, `array`, `set`, `expression_list`, `sequence_expression`): Create a `COLLECTION` node, recursively evaluate all non-punctuation children, connect each child element with edge `CONTAINER_ELEMENT`, and return the collection node ID.
   - **Key-Value Collections** (`dictionary`, `object`): Create a `COLLECTION` node, recursively evaluate each `pair` value, connect each value with edge `CONTAINER_ELEMENT`, and return the dictionary node ID.
   - **Transparent Wrappers** (`await_expression`, `as_expression`, `type_assertion`, `non_null_expression`, `unary_operator`): Recurse into the inner operand and pass through the inner expression node IDs.

---

## 3. Caveats

1. **Scope of Defect 1**: This investigation specifically addresses Defect 1 (DFG collection node loss). It does not implement Defect 2 (sink substring heuristic in `walker.py`) or Defect 3 (AST fallback variable scan). However, our prototype verifies that fixing Defect 1 cleanly resolves the false negative on `%` tuple formatting without conflicting with Defect 2/3.
2. **Collection Unpacking**: Advanced runtime collection manipulation (e.g. `*args`, `**kwargs` unpacking across complex dictionary merges) is not part of basic DFG def-use chains and remains out of scope for the Milestone 2 CWE-89 slice.
3. **Parameterized Queries Preservation**: Genuinely parameterized queries (e.g. `cursor.execute(query, (user_id,))`) must continue to be recognized as safe/sanitized. Our test harness verifies that passing `(user_id,)` as a secondary parameter argument maintains `sanitized=True` and `severity=LOW`.

## 4. Conclusion & Recommended Fix Strategy

### Recommended Changes to `codedee/codedee_server/app/graphs/dfg.py`
In `DFGBuilder._process_expression` (between Branch 6 at line 468 and Branch 7 at line 469), insert the following recursive handlers:

```python
        # 7. Parenthesized Expressions (Grouping)
        # Transparently unwrap and forward inner expression value nodes
        if node_type == "parenthesized_expression":
            inner_ids: List[str] = []
            for child in node.children:
                if child.type not in ("(", ")", ";"):
                    inner_ids.extend(self._process_expression(child, source_bytes, language, file_path, func_id, current_defs))
            if inner_ids:
                return inner_ids

        # 8. Collections & Sequences: tuple, list, array, set, expression_list, sequence_expression
        if node_type in ("tuple", "list", "array", "set", "expression_list", "sequence_expression"):
            coll_id = f"{func_id}::coll_{node.start_point.row + 1}_{node.start_point.column}"
            self.graph.add_node(
                coll_id,
                node_id=coll_id,
                var_name=node_text,
                file_path=file_path,
                line_number=node.start_point.row + 1,
                col_offset=node.start_point.column,
                node_kind="COLLECTION",
                expression_text=node_text,
                tainted=False,
                taint_source=None,
                ast_node=node,
            )
            for child in node.children:
                if child.type in ("(", ")", "[", "]", "{", "}", ",", ";"):
                    continue
                elem_ids = self._process_expression(child, source_bytes, language, file_path, func_id, current_defs)
                for eid in elem_ids:
                    self.graph.add_edge(eid, coll_id, flow_type="CONTAINER_ELEMENT", operation=node_type)
            return [coll_id]

        # 9. Dictionaries / Objects & Key-Value Pairs
        if node_type in ("dictionary", "object"):
            dict_id = f"{func_id}::dict_{node.start_point.row + 1}_{node.start_point.column}"
            self.graph.add_node(
                dict_id,
                node_id=dict_id,
                var_name=node_text,
                file_path=file_path,
                line_number=node.start_point.row + 1,
                col_offset=node.start_point.column,
                node_kind="COLLECTION",
                expression_text=node_text,
                tainted=False,
                taint_source=None,
                ast_node=node,
            )
            for child in node.children:
                if child.type in ("{", "}", ",", ";"):
                    continue
                val_ids = self._process_expression(child, source_bytes, language, file_path, func_id, current_defs)
                for vid in val_ids:
                    self.graph.add_edge(vid, dict_id, flow_type="CONTAINER_ELEMENT", operation="dict_entry")
            return [dict_id]

        if node_type == "pair":
            val_node = node.child_by_field_name("value") or (node.children[-1] if len(node.children) >= 3 else None)
            if val_node:
                return self._process_expression(val_node, source_bytes, language, file_path, func_id, current_defs)
            return []

        # 10. Syntactic wrappers / Type assertions (TS) / Await / Unary
        if node_type in ("await_expression", "as_expression", "type_assertion", "non_null_expression", "unary_operator", "unary_expression"):
            for child in node.children:
                if child.type not in ("await", "as", "!", "+", "-", "~", "not", "type_arguments", "predefined_type", "type_identifier"):
                    sub_ids = self._process_expression(child, source_bytes, language, file_path, func_id, current_defs)
                    if sub_ids:
                        return sub_ids
```
