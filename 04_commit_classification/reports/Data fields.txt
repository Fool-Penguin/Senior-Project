RQ1 metric
Complexity: [
Cyclomatic Complexity (CC): วัดจำนวนเส้นทางการตัดสินใจในโค้ด (เช่น if, else, while)เกณฑ์: ค่าเฉลี่ยต่อฟังก์ชันควร < 10 หาก > 15 แปลว่าโค้ดเริ่มซับซ้อนเกินไป บำรุงรักษายาก
Cognitive Complexity: วัดความยากง่ายที่ "สมองมนุษย์" จะเข้าใจโค้ดนั้นๆ (เช่น การเขียน if ซ้อน if หลายๆ ชั้นจะทำให้ค่านี้สูงริ่ว แม้ค่า CC อาจจะไม่สูงมาก)|
Lines of Code (LOC) per Method/Class: จำนวนบรรทัดของโค้ดต่อหนึ่งฟังก์ชันหรือหนึ่งคลาส คลาสที่ยาวเกินไป (God Class) จะแก้ไขยาก

Modularity & Coupling Metrics: [
Afferent Coupling (Ca): จำนวนโมดูลภายนอกที่วิ่งเข้ามาเรียกใช้งานโมดูลนี้ (ตัวชี้วัดความรับผิดชอบ)
Efferent Coupling (Ce): จำนวนโมดูลภายนอกที่โมดูลนี้วิ่งออกไปเรียกใช้งาน (ตัวชี้วัดความพึ่งพาพิง)
Instability (I): อัตราส่วนความไม่เสถียร คำนวณจาก I = Ce / (Ca + Ce)แปลผล: ถ้าค่าเข้าใกล้ 1 แปลว่าโมดูลนั้นเปลี่ยนแฝงง่าย ไม่มีใครพึ่งพา แต่ถ้าเข้าใกล้ 0 แปลว่าโมดูลนั้นเป็นแกนหลัก เปลี่ยนแปลงยากเพราะจะกระทบคนอื่นไปทั่ว
Lack of Cohesion in Methods (LCOM): วัดว่าฟังก์ชันต่างๆ ในคลาสเดียวกัน มีการใช้ตัวแปรส่วนกลางร่วมกันไหม หากค่า LCOM สูง แปลว่าคลาสนั้นทำงานสะเปะสะปะ ไม่เป็นเอกภาพ (Low Cohesion) ควรแตกออกเป็นคลาสย่อยๆ

3. ตัวชี้วัดคุณภาพซอฟต์แวร์อื่นๆ ที่เกี่ยวข้องกับ Maintainabilityนอกเหนือจากโครงสร้างโค้ดและการจัดการ Issue แล้ว ตามมาตรฐานสากล (เช่น ISO/IEC 25010) ยังมีตัวชี้วัดเหล่านี้ที่สะท้อนความสามารถในการบำรุงรักษาซอฟต์แวร์ได้อย่างดี:
Code Smell Density (ความหนาแน่นของจุดบกพร่องในโค้ด): จำนวนจุดที่โค้ดเขียนผิดหลักการออกแบบที่ดี (เช่น Long Parameter List, Dead Code, Duplicated Code) ต่อจำนวนบรรทัดซอฟต์แวร์
Technical Debt / Remediation Effort (หนี้ทางเทคนิค): คำนวณออกมาเป็น "เวลา" (เช่น เป็นชั่วโมงหรือเป็นวัน) ที่นักพัฒนาต้องใช้ในการเคลียร์ Code Smell ทั้งหมดให้โค้ดกลับมาสะอาด (เครื่องมืออย่าง SonarQube สามารถคำนวณค่านี้ออกมาได้โดยอัตโนมัติ)
Test Coverage (ความครอบคลุมของการทดสอบ): เปอร์เซ็นต์ของซอร์สโค้ดที่ถูกทดสอบโดย Unit Test ยิ่งมี Coverage สูง โค้ดยิ่งมี Maintainability สูง เพราะเวลาปรับปรุงโค้ด (Refactoring) จะมีระบบตรวจสอบอัตโนมัติว่าทำระบบพังตรงไหนไหม
Comment Density (ความหนาแน่นของคำอธิบายโค้ด): อัตราส่วนของบรรทัดที่เป็น Comment เทียบกับบรรทัดที่เป็น Code จริง เพื่อดูว่าโค้ดมีการอธิบายการทำงานในจุดที่ซับซ้อนไว้ดีเพียงใด
